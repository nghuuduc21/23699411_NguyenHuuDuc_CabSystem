## 2. Lệnh đã chạy

```bash
# Dựng hệ thống (Docker Desktop đang tắt lúc bắt đầu, đã bật)
docker compose up -d --build

# Đặt lại dữ liệu đặt xe / thanh toán / chuyến về seed (trước mỗi lượt chạy và sau cùng)
docker exec booking-db psql -U cab -d booking -c "DROP SCHEMA public CASCADE; CREATE SCHEMA public;"
docker exec payment-db psql -U cab -d payment -c "DROP SCHEMA public CASCADE; CREATE SCHEMA public;"
docker exec trip-db psql -U cab -d trip -c "DROP SCHEMA public CASCADE; CREATE SCHEMA public;"
docker compose restart booking-service payment-service trip-service

# End-to-end nghiệp vụ (không dừng container) — trên dữ liệu vừa đặt lại
cd tests && npm run test:nghiep-vu

# End-to-end dừng / restart service (file 90 cũ + file 91 mới)
cd tests && npm run test:dung-service

# Postman — trên dữ liệu vừa đặt lại
npx -y newman@6.2.1 run postman/cab.postman_collection.json

# Dọn dữ liệu Postman (tài khoản 0399… / 0599…, TX7 về PENDING) như báo cáo 2026-10-04 mục 2, rồi đặt lại booking / payment / trip như trên
```

Tiền điều kiện của file 11, 12: dữ liệu booking / payment / trip **vừa đặt lại về seed** (KH1 có đúng 7 booking; payment 7 `PENDING`; không có Offer chờ). Hook `before` kiểm và báo rõ nếu thiếu. Mã do API tạo chỉ được khẳng định đúng 1000 khi chưa có booking / payment nào ≥ 1000 (hàm `isFreshData`); lượt chạy chính thức trên dữ liệu vừa đặt lại cho `booking_id` 1000, `payment_id` 1000, `offer_id` 1000, `trip_id` 1000 đúng như AC-DX-05, 06, 19.

Hết hạn (AC-DX-16, AC-TT-10) **không đổi `.env`**: test chạy `UPDATE driver_offers SET expires_at = now() WHERE offer_id = …` ở `booking-db`, hoặc `UPDATE payments SET expires_at = now() WHERE payment_id = …` ở `payment-db`; tiến trình nền 1 giây tự xử lý.
